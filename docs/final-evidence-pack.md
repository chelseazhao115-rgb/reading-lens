> 状态：证据已冻结，进入Demo录制与求职材料收尾。所有数字均来自下列Artifact或API。

## 一句话项目定义

面向雅思阅读5.5–6.5分学习者的AI错因诊断教练：要求学生提交答案、原文证据和思考过程，按固定因果链识别最早失败步骤，并用针对性微练习与迁移题验证修正。

## 已冻结事实

### 产品与工程

- 核心闭环：Answer → Evidence → Reasoning → Diagnosis → Correction → Micro Exercise → Transfer → Learner State。
- 五类一级错因：定位、同义替换、句子理解、题型策略、推理越界；另有信息不足、题目含糊和数据错误三种安全状态。
- 标准证据与学生证据均先做确定性原文匹配；证据无效时停止诊断。
- Provider输出经过结构、因果链、答案一致性、置信度和预算闸门。
- 自动测试：186/186通过。

## 3分钟项目介绍

### 0:00–0:35 问题

雅思阅读学生通常知道答案错了，却不知道问题发生在定位、同义替换、句子理解、题型规则还是推理边界。普通解析解释正确答案，但不能形成可复用的错因判断。

### 0:35–1:15 方案

我把自己的阅读教学判断拆成Evidence-first因果链：学生必须提交答案、证据和思路；系统先验证证据，再判断最早失败步骤，随后给出Where、Why、Fix，并生成同错因微练习和迁移题。

### 1:15–2:05 AI与评测

我没有把LLM当自由聊天工具，而是使用结构化输出、固定taxonomy、确定性证据校验、置信度与安全拒答。DeepSeek在8条困难边界集上从v1的50%提升至v3的87.5%，不安全诊断从50%降到0；但仍有一条契约失败，因此没有把候选模型自动切到学生端。

### 2:05–2:40 用户迭代

5名目标用户首测中，核心路径无指导完成率100%，诊断理解率80%。真实测试暴露了P004中“NOT GIVEN”词组触发误判，以及反馈缺少具体行动的问题。我把失败保存成回归案例，修复关键词逻辑并重写五类证据级反馈。

### 2:40–3:00 最终结果与边界

修复后3名新用户均能复述具体错点、下一步动作和练习关系；10条微练习教师审核完成，六维有效率80%、盲答一致率100%、训练目标一致率80%。当前证据只支持探索性可用性，不支持提分结论；正式50条Teacher Gold、长期学习效果和模型上线属于Future Improvements。

## 面试追问准备

1. 为什么不用聊天机器人？——错因诊断需要可审计的固定因果链，而不是开放式回答。
2. 为什么必须提交证据？——它既是诊断信号，也是防止模型引用不存在原文的安全边界。
3. 为什么DeepSeek 87.5%仍不上线？——样本只有8条且由项目作者标注，同时仍有12.5%契约失败；证据不足以替代稳定规则流程。
4. 最大失败是什么？——P004关键词捷径把正确推理误判为题型策略错误；说明规则命中不等于语义理解。
5. 如何避免夸大效果？——分开标记合成、作者评测、独立教师和真实用户数据；小样本只报告探索性结果，不声称提分。
6. 如果再做一轮？——优先扩充独立Teacher Gold并验证长期迁移，不增加题库、RAG或多Agent复杂度。

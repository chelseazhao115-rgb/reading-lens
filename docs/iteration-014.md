# Iteration 014: Recruiter Case Study

## Before

- 产品、评测、审核和用户研究页面彼此独立，招聘者无法在3至5分钟内建立完整产品叙事。
- 已有证据没有统一入口，容易把合成框架基线误解为官方模型效果。
- 作品集审计项保持 PARTIAL，明确缺少统一案例页。

## Change

- 新增 `/case-study.html`，围绕用户问题、Evidence + Reasoning、五类错因、固定因果链、安全机制、失败边界和验证计划形成单页叙事。
- 嵌入真实运行产品，而不是静态视觉稿。
- 实时读取 Eval、诊断教师审核、微练习审核和本地真实用户研究状态；读取失败时拒绝展示缓存或推测结果。
- 合成 Evidence Accuracy 明确标注为框架回归基线，教师 Gold 不足时官方结果保持 N/A。
- 在产品、Analytics、Eval Results 和 README 中加入案例页入口。

## After

- 9项招聘者叙事要求均有对应页面内容与自动化回归保护。
- 当前状态准确显示诊断 Gold 0/50、微练习审核 0/10、首次用户 0/5，未制造模型或学习效果结论。
- 页面采用响应式单页结构，并在真实浏览器中完成桌面视图和动态数据验证。

## Regression

- 全量测试、评测和 JavaScript 语法检查通过。
- 核心诊断、练习、审核、Analytics 和用户研究逻辑未改动。

## Remaining Risk

- 尚未用招聘者或产品经理完成3至5分钟理解测试。
- 教师 Gold、微练习教师审核和真实目标用户数据仍为0，案例只能展示验证系统，不能宣称质量目标达成。

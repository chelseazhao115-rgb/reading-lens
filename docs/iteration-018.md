# Iteration 018: Provider Benchmark and Promotion Gate

## Before

- Provider输出安全契约已经建立，但不同候选模型没有统一的离线比较入口。
- 准确率、拒答、安全、延迟和成本没有形成明确的上线判断。
- 更高准确率但更高误诊率或超预算的模型仍可能被主观选择。

## Change

- 新增通用异步Provider benchmark，固定运行8条自然表达困难边界。
- 统一输出精确分类率、不安全诊断率、拒答率、输出闸门失败率、平均/P95延迟、总成本和单次成本。
- 建立五道同时成立的promotion gate：安全、分类提升、覆盖提升、输出契约和预算。
- 默认命令只运行本地`rule-baseline`且预算为0，不配置、不探测也不调用任何外部Provider。
- Eval Results新增Provider benchmark与逐项发布判断，任何候选都不会自动切换线上Provider。

## After

- 规则参考基线：精确分类12.5%，不安全诊断0%，拒答87.5%，输出闸门失败0%，总成本0美元。
- 规则基线通过安全、契约和预算，但未通过分类提升与覆盖提升，因此不能自我晋升。
- 未来候选必须在同一数据和口径下同时改善质量与覆盖，并保持不安全诊断不高于10%。
- 教师盲审在本轮观察期间由0增长至至少3条合格Gold；审核仍在继续，官方指标保持N/A。

## Regression

- 83项自动化测试通过。
- 主评测、困难边界、输出契约、Teacher Gold门槛和产品核心闭环无回归。

## Remaining Risk

- 困难边界标签仍是项目作者标签，Provider benchmark不是Teacher Gold结果。
- 当前只有规则参考基线，尚未获得真实语义候选的准确率、延迟或成本。
- 当前Gold仍不足50条，不能计算任何官方一致率。

# Iteration 058 — 微练习盲审语义ID泄露修复

## Before

- 微练习审核宣称在锁定前隐藏标准答案和目标错因，API也删除了`answer`与`target_error`。
- 公开案例仍携带内部ID，例如`location_immediate_01`；ID直接泄露目标错因为`location`并暴露练习阶段。
- 客户端把该ID渲染为标题，导致教师在选择“主要训练错因”前已被提示，未来10条盲判证据会失效。
- 当前人工审核为0/10，因此尚未产生受污染的教师记录。

## Change

- 新增稳定无语义编号`blind-exercise-001`至`blind-exercise-010`。
- 公开API永久删除内部`id`，锁定盲判前同时删除`answer`、`target_error`和`stage`。
- 客户端只展示“盲审练习01”等中性标题，并在揭示与最终保存时提交`blind_id`。
- 服务端根据盲编号映射内部记录；不再接受内部ID作为公开保存标识。
- 新增盲编号稳定性、内部ID隐藏、阶段延迟揭示和服务端映射回归断言。

## After

- 173/173项自动化测试通过。
- 临时4174验证实例的首条公开载荷：`blind_id=blind-exercise-001`，不存在内部`id`、标准答案、目标错因或阶段。
- 使用内部语义ID调用揭示接口返回404，审核进度保持盲判0/10、Gold 0/10。
- 浏览器第一阶段显示“盲审练习01”；标准答案、Gold元信息、内部ID和阶段均不可见。

## Regression

- 五个一级错因仍作为教师必须独立选择的候选项显示；这不是Gold泄露。
- 锁定有效盲判后，服务端仍会返回答案、目标错因和阶段供六维复核。
- 本轮没有替教师作答、没有写入审核记录，微练习人工证据仍真实为0/10。

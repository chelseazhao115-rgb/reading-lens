# Iteration 043 — 复核保存防丢失与作者进度纠正

## Before

- 用户认为案例06–08已经完成复核，但服务端记录的状态、标签与保存时间均未变化，说明表单修改没有通过状态按钮落盘。
- 页面允许未保存修改后切换案例，缺少明显的脏状态反馈。
- 作者QA页的“作者QA通过”错误读取`gold_eligible`，把真实8条批准显示为0。

## Change

- 表单字段改变后立即显示“当前修改尚未保存”，并要求点击批准、需修订或拒绝按钮保存。
- 未保存时拦截上一条、下一条及离开页面，保存成功后解除拦截。
- 保存成功后持续显示案例编号、服务端保存时间和最终状态，不再被案例重绘立即覆盖。
- 作者QA进度改为显示`progress.approved`；独立教师轨道仍显示`progress.gold_eligible`。
- 不代替作者修改或提交案例06–08的专业判断。

## After

- 自动化测试145项全部通过，其中保存确认文案已由可执行单元测试覆盖。
- 浏览器实测：修改案例06说明后点击“下一条”，URL与页面均停留在案例06，并显示未保存提醒。
- 权威API仍为10条已处理、8条批准、1条拒绝、1条需修订；案例06–08保存时间未更新，因此不能宣称三条已复核完成。

## Regression

- 测试覆盖未保存提示、导航拦截、离页提醒和两条轨道的进度口径；浏览器回归额外发现并修复了一处错误变量名。
- 未写入模拟审核数据，Teacher Gold仍为0/50。

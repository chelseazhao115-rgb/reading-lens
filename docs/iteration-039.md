# Iteration 039 — 教师试审真正盲化与进度口径

## Before

- 教师页面虽然不显示`proposed_primary_error`与模型预测，却直接展示`review_location_01`等语义内部ID，审核者可从ID猜出作者标签。
- 公开API同样下发内部ID，盲审只停留在字段隐藏层面。
- 24条历史流程测试记录被正确排除出Gold，但页面总进度显示“24/50已处理”，试审显示“10/10已处理”，容易让真实教师误以为任务已完成。
- 首批10条仅覆盖五类主要错因各两条，没有在继续剩余40条前验证信息不足、题目含糊和数据错误三种安全状态。

## Change

- 公开审核案例改用`blind-case-001`形式的无语义编号；内部ID不再下发，保存接口只接受盲审编号并在服务端映射。
- 页面标题改为“盲审案例01”，不展示任何包含错因名称的标识。
- 总进度与试审进度只统计当前`diagnostic-causal-blind-v3`协议、合格教师编号、资质声明、服务器时间和专业说明完整的操作。
- 历史流程记录继续保留，但仅进入`provenance_excluded`或“来源问题”，不占真实完成进度。
- 10条试审调整为五类主要错因各至少1条、三种特殊状态各1条，并补充同义替换与题型策略边界样本。

## After

- 自动化测试141项全部通过；合成框架基线保持100%，Teacher Gold仍为0/50。
- 运行时API首条案例只含`blind_id=blind-case-001`，不含内部`id`、作者标签、预测标签或置信度。
- 浏览器显示“0/50已处理”“0/10试审已处理”“10条样本/来源问题”，案例标题为“盲审案例01”。
- 公开页面仍展示固定八类taxonomy供教师选择，但不提供任何当前案例的标签暗示。

## Regression

- 服务端仍通过内部映射保存到正确候选，乐观并发版本令牌不变。
- 24条历史流程记录没有删除，仍可审计且不能进入Gold。
- 冻结预测完整性继续通过；正式教师指标因Gold不足保持N/A。
- 尚未提交任何真实教师判断，不能把本轮浏览器验证计入试审或Gold。

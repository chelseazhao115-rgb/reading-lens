# Iteration 026 — 真实用户研究会话隔离

## Before

- 研究工具生成`/?research_session=...`专属链接，但服务器把查询参数当作文件路径，实际返回404。
- 研究事件虽然带匿名会话ID，Learner State与Workflow仍使用全局存储键；下一位参与者可能继承上一位的答案、诊断和累计计数。
- 研究页同步从全局Learner State读取后再过滤，无法形成强隔离边界。

## Change

- 服务器统一使用URL pathname路由，静态页面和API均安全忽略查询参数。
- Demo继续使用原存储键；每个合法`rs_...`会话使用独立Learner State与Workflow命名空间。
- 产品先激活URL中的研究会话，再加载对应状态，避免初始化阶段读取Demo数据。
- 研究页同步直接加载指定会话状态，再验证同会话有序事件链。
- 新增路由、两会话Learner State和两会话Workflow隔离回归。

## After

- 专属研究链接由HTTP 404修复为200并正确返回产品首页。
- 浏览器双会话实测：参与者A完成诊断后计数1且刷新可恢复诊断与练习；参与者B刷新后诊断不可见且计数0。
- 两个会话控制台错误均为0。
- 自动化测试由106项增至110项并全部通过。

## Regression

- 普通Demo数据仍使用原命名空间，不受研究会话影响。
- 同一研究会话内的刷新恢复能力保持不变。
- 未修改真实研究记录、教师审核记录、核心用户或五类错因。

# Iteration 055 — 把DeepSeek失败修正写成可审计作品集证据

## Before

- DeepSeek真实付费评测已经完成，但评测页和案例页只展示规则基线的12.5%准确率与87.5%拒答。
- 最能体现AI产品判断的“v1不安全失败→v2安全拒答”过程没有进入作品集。
- 部分案例文案仍写“尚无真实语义模型证据”，与实际Artifact矛盾。

## Change

- 从v2的1条smoke和7条remaining原始Artifact重新计算8条合并指标、P95延迟、成本、契约失败和晋级门槛。
- v1只使用Iteration 046中保留的汇总，并明确标记逐条Artifact未保留；不把低强度证据伪装成可逐条复算。
- `/api/eval-results`新增候选Provider证据，严格标记为项目作者困难集、非Teacher Gold、非学习效果。
- 评测页新增DeepSeek v1→v2专栏；案例页新增关键结果卡，并同步修正失败边界和盲回忆核验文案。

## After

- 169/169项自动化测试通过；合成框架评测保持12/12。
- v2按8条原始记录重新计算：精确分类6/8（75%）、不安全诊断0/8、拒答2/8、契约失败2/8、P95 2299.17ms、总成本$0.00187866。
- v1文档汇总为4/8（50%）且不安全诊断4/8（50%）；v2相对提升25个百分点，并把已观察到的不安全错误降低50个百分点。
- 输出契约仍未通过，因此晋级门槛保持失败，学生产品继续使用规则Provider。
- 浏览器确认评测页和案例页同时显示50%→75%、50%→0%、非Teacher Gold、总成本与未晋级状态。

## Regression

- v1没有逐条原始Artifact，页面明确暴露这一限制；v2保留8/8逐条证据。
- 8条项目作者标签不能替代50条独立教师Gold，也不能证明学习效果。

# Iteration 005 — Blind Teacher Review Workspace

## Before

- The 50-case review pack required direct CSV editing.
- Proposed labels were present in the CSV and could anchor the reviewer.
- There was no local progress view or validated server-side save action.

## Change

- Added a local blind-review page at `/review.html`.
- The API excludes `proposed_primary_error` from browser payloads.
- Added progress for reviewed, approved and needs-revision cases.
- Added server-side validation for status, reviewer label and reviewer identity.
- Review timestamp is generated by the server.
- Writes use a temporary file and rename only after validating all 50 records.
- Bound the local server to `127.0.0.1`.

## After

- 35/35 tests pass.
- GET `/api/reviews` returned 50 pending cases and `blind_review=true`.
- API response did not expose the proposed label.
- Browser rendered the complete first case and all review controls with no console errors.
- An invalid approval without reviewer ID was rejected and did not create `reviewed.json`.
- No teacher labels were saved during automated verification.

## Regression

- Gold eligible remains zero, correctly.
- The interface reduces review friction but cannot replace domain judgment.
- The review dataset remains balanced synthetic data and does not estimate real error prevalence.

## Next

- The IELTS reading teacher reviews the 50 cases in the blind interface.
- Rejected or needs-revision cases are corrected before inclusion.
- After 50 approved cases, run the official comparison and confusion matrix.

# Iteration 037 — 用户证据硬闸门与重试遥测去重

## Before

- 无效证据重试会重复写入`answer_submitted`和`evidence_submitted`，并重复累计从页面打开开始计算的证据用时。
- 自动化测试只证明标准证据必须来自passage；浏览器实测发现用户粘贴一段完全不存在于passage的文字时，系统仍生成确定诊断、微练习并锁定表单。
- 证据拒绝提示直接暴露内部原因码，不告诉用户下一步如何修正。

## Change

- 工作流草稿升级为Schema 3，持久化诊断尝试次数、答案事件、已接受证据事件和证据计时去重标记。
- `answer_submitted`只在本题第一次诊断尝试记录；`evidence_submitted`与证据用时只在证据通过且诊断进入终态后记录。
- 无效尝试改记`evidence_validation_failed`，并记录尝试序号；刷新后重试仍不会重复计算。
- 新增用户证据确定性校验：quote必须逐字存在于服务端权威passage；校验失败时Provider调用次数为0，不生成错因或微练习。
- passage中存在但位置错误的原句仍可进入定位错误诊断，避免把“证据选错”与“证据伪造/误粘贴”混为一谈。
- 将内部原因码映射为可执行的中文提示，引导用户重新划选或粘贴原句。

## After

- 自动化测试由133项增至139项，全部通过。
- 12条合成框架基线保持100%，不安全过度诊断率0%，结构微练习有效率100%；这些仍仅是项目作者合成基线。
- 浏览器复现同一伪造证据：修复前产生80%置信度的“定位错误”并错误锁定；修复后证据被拒绝、诊断计数保持0、表单可编辑。
- 同一会话改用passage原句后成功进入终态诊断，证明失败恢复没有阻塞正常路径。

## Regression

- 证据确实来自passage但与标准证据位置不同的案例，仍可由因果链判断为`location`。
- 标准证据校验、Provider结构契约、即时练习与迁移闭环无回退。
- Teacher Gold仍为0/50，微练习教师审核仍为0/10，真实用户验证仍未开始；合成基线不替代外部证据。
- 本轮评测同时发现历史非Gold审核记录存在冻结预测完整性错误，官方Teacher指标因此保持禁用；需要下一轮修复其隔离语义，不能等到收集完新Gold后再处理。

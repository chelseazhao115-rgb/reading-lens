# Iteration 068 — 审核邀请文案跟随真实批次

## Before

- 验证工作台正确显示诊断Gold 10/50并指向CASE 11。
- 进入诊断审核启动页后，底部静态邀请文案仍写“先独立盲审10条”，与当前阶段冲突，可能导致下一位教师重复审核CASE 1–10。

## Change

- `deriveReviewHandoffState`现在同时生成阶段标题、批次范围、执行说明和邀请文字。
- 通过试审后，每批固定为下一条待审案例起的最多10条；当前真实状态生成CASE 11–20。
- 暂停状态明确禁止继续招募；50条完成状态明确停止招募；首轮未完成时仍保留10条试审说明。
- 邀请文字继续要求雅思阅读教学/教研资质、作者独立性、`teacher-`匿名编号和本机或屏幕共享环境。

## After

- 真实页面显示“本次只完成CASE 11–20”“前10条已经保存，不要重复审核”。
- 主CTA为“从第11条继续”，链接`/review.html?case=11`。
- 邀请文字明确当前10条区间，不再要求教师猜测进度。

## Regression

- 185/185自动测试通过。
- 未改写任何已保存教师记录，也没有自动提交审核。
- 试审异常和全部完成两种状态都有防误招募测试。

## Next

- 工程侧已没有阻挡CASE 11–20审核的已知问题；下一项证据只能由合格独立教师真实完成。

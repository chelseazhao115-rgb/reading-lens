## 1. 项目到底在做什么

目标用户是雅思阅读约 5.5–6.5 分、看懂解析后仍重复犯错的学习者。产品假设是：只知道答案对错不足以指导下一步学习，需要结合学生选择的原文证据与判断理由，识别可能的主要错因，再安排对应练习。

核心路径：提交答案 → 提交证据与理由 → 判断主要错因 → 查看具体修正动作 → 即时练习与重试 → 新材料无提示迁移 → 保存学习记录。

五类错因是定位、同义替换、句子理解、题型策略、推理越界；另有信息不足、题目含糊、数据错误等拒答状态。这是一套项目设计的诊断框架，现有证据不足以把它称为已验证的认知因果模型。

## 5. 需要重点讲清的四个产品判断

1. **输入摩擦与诊断价值的取舍。** 学生为什么愿意多写证据与理由？5/5 能完成仅证明能用，没有证明他们在真实复盘中愿意反复用。进一步验证应看真实任务中的自发选择、退出位置与复访理由。
2. **规则与 LLM 的职责。** 原文引用匹配、格式检查、判分可由确定性逻辑承担；复杂自然语言推理需要模型能力。当前规则大量拒答说明覆盖有限，模型未上线则说明已有发布判断，两者都要讲清。
3. **诊断正确与练习有效的区别。** 8/10 微练习通过是内容质量信号；学生完成迁移是行为信号；长期陌生材料改善才更接近学习价值。三层指标不能互相替代。
4. **真实使用入口是否合理。** PDF 导入需补正确答案和标准证据，若由学生本人配置，会提前看到标准信息。因此更适合教师准备后的练习或做题后复盘；不能直接把它当未见答案的独立测验。扩展入口需围绕目标场景继续验证。

再注意两个表述：页面里的「低置信度进入教师复核」目前主要是拒答/建议教师确认，没有证据证明学生个案已自动派单到教师服务；「找到最早失败步骤」是框架内的判断策略，不能称为已证明真实认知原因。

## 6. 一周内不做与投递后可选增强

这一周冻结题库扩充、账号体系、复杂云部署、RAG、多 Agent、全新 UI、额外模型付费迭代和长期提分实验。现有 PDF、插件与错词功能放在附录，面试主线聚焦诊断闭环。

如果投递后只追加一轮实质验证，优先顺序建议如下：

1. 用未参与 Prompt 调整的新案例作为留出集，并增加教师独立标签。不要继续只在已反复修改 Prompt 的 8 条开发案例上追求更高数字。50 条是本项目的报告门槛，不是自动保证可信度的通用标准。
2. 对两条未通过微练习澄清标注理由，按真实教研反馈修订后复审，保留原结果和版本。不能自行把教师的 needs_revision 改成通过。
3. 通过质量、覆盖、契约、延迟和成本要求后，做小范围受控模型试点，再考虑学生端放行。不要为了简历里多一个“上线”跳过评测。
4. 有持续用户后，用新材料做延迟复测，报告样本、难度、观察窗口和流失；再逐步讨论学习价值和复访。
